📄 目的地详情
Where2Go 阶段2b · 地图:高德 JS API 2.0(底图与 POI 同源、坐标 GCJ-02;JS key 与安全密钥由 /api/map-config 运行时下发,不进 git、不写在本页)· 数据:高德 v3 四分类检索 (place/around + 包围盒分格 place/polygon)抓取后入 SQLite, 同一「城市 + 分段」二次查询只读库不触网 · 归类优先级 滑雪 > 运动 > 人文美食 > 自然, 按高德 POI id 去重(osm_type="amap";存量 OSM 行按 (type, id))、一地只属一类 · 一句话简介由 LLM 生成并按 POI 缓存 · 高德覆盖不足处由人工种子数据垫底(popup 标注来源=种子,坐标是 WGS-84、与高德底图可能偏差 ≤500m)· 路线:驾车时长/里程来自高德驾车路线(费用为估算,过路费按 toll_distance × 区域费率),铁路/飞机为经验估算, 一律标注「估算 · 非实时 · 以官方为准」,只用 deep-link 跳转官方、不代订不抓价 · 住宿:高德住宿类 POI 检索目的地周边落脚点,价格与简介为 AI 预估参考价 (强标注「AI 预估 · 仅供参考 · 以 OTA 实时为准」),不代订、不抓 OTA 实时价 · 行程方案:勾选收藏组合后存进后端(SQLite),总花费由后端按收藏快照的「当时口径」估算 (quote.kind=estimate + note 双标注),仅供参考、不代订不抓实时价 · AI 推荐:地图默认只画后端推荐的 3~5 个目的地(可切「全部目的地」),LLM 没 key / 调用失败时 降级为「按距离推荐」并在页面上标明原因 · 长介绍:地图下方列表分批懒加载(每批 10 条、推荐条优先), 按 POI 缓存在库里、只补还没有的 · 收藏两层:目的地为父节点,它的路线与住宿收藏挂在下面 (旧收藏没有父级标注时落「未归类」,一条不丢)· 起点地理编码:高德主路径 + Photon / Nominatim 降级,状态栏标注本次是谁答的 (geocoder=amap / photon / nominatim;三个源都没答时 none,降级成坐标起点,范围圈照画、分段照查)· 目的地列表分页:首屏每页 15 条,「加载更多」按 offset 逐页取;翻到库尾时带 more=true 让后端再抓一轮 高德检索(约 3-20s,期间提示「正在扩抓更多目的地…」),has_more=false 就没有更多了 · 路线费用 v2:驾车给「整车≤4人 / 人均」双标 + 构成明细(高速费 toll / 油费 fuel,高速里程来源 amap_toll_distance|heuristic),铁路标 price_source(seed = 参考真实票价 / estimate = 分档费率估算), 机票给公布价锚定区间「¥A–B(浮动)」;给不出票价时不编数字,只留 OTA deep-link 看实时价 · 住宿空态分三档:reason=no_data(附近没找到住宿,给最近一家的距离)/ datasource_error(数据源暂时不可用, 可重试)/ timeout(查询超时,请稍后再试);价格还在后台回填(estimating=true)时显示「AI 估价生成中,稍后刷新」
