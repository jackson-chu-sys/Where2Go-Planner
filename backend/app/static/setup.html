🧭 Where2Go · 配置向导

容器版没有 .env 文件:在这里填入你自己的 key,保存后即时生效、无需重启。配置存在容器数据卷的数据库里;若容器环境变量已设同名变量,以环境变量为准。key 永不回显明文。

① 高德 Web服务 key ② 高德 JS key + 安全密钥 ③ LLM(可选) ④ 完成

第 1 步 · 高德 Web 服务 key *

后端 POI 检索 / 地理编码 / 驾车路线全靠它。缺了它,首页地图和搜索都不可用。

怎么申请(免费,约 3 分钟):
  1. 打开 高德开放平台控制台 → 应用管理 → 我的应用(未注册先注册,个人开发者实名认证即可)。
  2. 「创建新应用」→ 应用里「添加 Key」。
  3. 服务平台务必选「Web服务」(不是「Web端(JS API)」!)。选错平台,后端调用会报 USERKEY_PLAT_NOMATCH(infocode 10009)。
  4. 创建后复制那串 key,粘贴到下面。
点「校验」会用这张 key 真调一次高德地理编码(只打一次请求,不会触发限流);通过后自动保存。

第 2 步 · 高德 Web端(JS API)key + 安全密钥 *

首页地图(高德 JS API 2.0)用这两个值加载。与第 1 步的 key 是同一应用下的两把不同 key,平台隔离、不能混用。

血泪坑,请照抄:
  1. 在同一个应用里再「添加 Key」,服务平台选 「Web端(JS API)」。
  2. 创建 JS key 时会同时给出一个安全密钥(securityJsCode)——两个都要复制。
  3. 把「Web服务」key 填到这里、或把 JS key 填到第 1 步,都会报 USERKEY_PLAT_NOMATCH(infocode 10009)。
  4. 安全密钥缺失或填错 → 首页地图整块空白,浏览器控制台报 INVALID_USER_SCODE。本向导保存后,首页会在加载地图脚本之前写入 window._AMapSecurityConfig,顺序已处理好,你只需要把值填对。
点「校验」会拿 JS key 打一次 REST 探针:被高德以「10009 平台不符」拒绝 = 恰好证明它是真的 JS key,即校验通过。安全密钥只在浏览器加载地图时使用,服务端无法预先校验。

第 3 步 · LLM(可选)

用于 POI 一句话简介与 AI 行程推荐。不配也能用:简介留空、AI 推荐降级,地图与检索照常。

点「测试」会发一条 1-token 的测试消息(可能产生极小额费用);也可以直接跳过。
