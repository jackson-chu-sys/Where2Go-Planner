## 2. 界面:地图模式(替代文字列表)

### 技术:Leaflet + OSM 瓦片(免费,已定)
- 自由/OSM 标准瓦片;中国区可后续换高德瓦片(仅展示,不需 key 商用版,或产品化再说)。

### 交互(需求 M1.05 + 神朱反馈)
1. 页面加载 → 地图以**起点**(城市/定位)为中心,画一个**当前选中距离段的圆环/范围圈**。
2. 目的地以**彩色图标 pin** 标注在圆环带内,图标**按分类着色/形状**(自然=绿山、人文美食=橙碗/建筑、滑雪=蓝雪、运动=红球)。
3. 点图标 → **弹出简介卡片**(Popup):名称、分类、距起点、**一句话简介**、多交通方式(驾车/铁路/飞机时间)、星级/季节等类别字段(依 M1.08~M1.11)。
4. 距离分段仍用环形 50-100…500,切换时**只重绘该带内的 pin**(数据已按 band 检索)。
5. 起点可改城市(搜索框)→ 地图/范围圈重定位。保留"我的位置"按钮(浏览器定位 → Nominatim reverse)。

### 前端结构(从单页裸 JS 升级)
- 采用 **React + Vite**?—— POC 是原生单 HTML。**建议阶段 1 保持轻量**,用 Leaflet 可直接嵌原生 JS,不必立刻上 React 全家桶(避免过度工程)。若神朱确定要产品化走 React,再迁。**此处默认:原生 + Leaflet 起步**(后端 API 不变,未来换 React 只重写前端)。
- 备选:Hermes browser_exec 可对本页面做自动化 QA(已记记忆)。

## 3. 分类:回到需求文档四类,消除重复

### 根因
POC 用 `natural=peak`/`tourism=attraction` 直接当"类",OSM 地物多 tag 并存 → 重复。**分类必须是产品语义,不是 OSM tag 的 1:1。**

### 四分类定义与检索策略(阶段 1 落地)

> 关键设计:**每个地物归入唯一分类(priority 判定),同一实体跨 tag 时按优先级去重**,绝不让一个点出现在两类。

| 分类(需求) | 产品含义 | OSM 识别线索 | 简介/卡片字段 |
|---|---|---|---|
| **自然风光** | 山/湖/瀑布/公园等自然景观 | `natural=peak/waterfall/water`、`tourism=attraction`∩自然、`leisure=nature_reserve`、`place=island` | 名称、距起点、海拔/面积、最佳季节、一句话简介 |
| **小城人文美食** | 古镇/人文街区/特色美食 | `tourism=attraction`(古镇)、`historic=*`、`amenity=restaurant` 聚类、`place=town`+美食 POI | 名称、人文背景、必吃/特色、烟火气 |
| **滑雪场** | 滑雪目的地 | `piste:type=*`、`leisure=sports_centre`+ski、`sport=skiing` | 名称、面积、雪道数、雪道分级、特点、评价 |
| **运动** | 特定运动场所 | `sport=*`、`leisure=sports_centre/pitch/stadium`、高尔夫/攀岩/骑行等 | 名称、项目、场地/装备、适宜人群 |

### 落地机制(重要——分类要去重 + 保覆盖面)
1. **检索**:按当前距离段的上限半径,一次性查**多类相关 tag 的并集**(而不是每类单独查造成重复)。
2. **归类优先级**(每 POI 只入一类):滑雪(最专一)→ 运动 → 人文美食 → 自然风光。命中高优先级即归类,不再进低优先级。
3. **去重键**:OSM `id + type`;同实体多 tag 已被优先级规则消化。
4. **简介生成**:名称/坐标来自 OSM,简介文案由 **LLM 生成并缓存**(M1.06 的 AI 推荐在此模块接入),每 POI 存一条。POC 未做 LLM,阶段 1 补上。

### 数据支撑现实(需在产品注明)
- OSM **中国滑雪场覆盖差**(实测北京周边 piste tag 为空)——滑雪类可能大量缺数据。对策:滑雪/小众类从 OSM 拿不到的,阶段 1 先用少量**种子数据**(人工/LLM 补录坐标与简介)垫底,标注来源。**这一点神朱需知悉**:免费源对"滑雪场/运动"这类小众目的地的国内覆盖不足,是产品级限制。

## 6. 风险与前置确认

1. **OSM 国内小众分类(滑雪/运动)覆盖不足** → 阶段 1b ✅ 已定(神朱):接受现状,种子垫底,后期稳定再切高德/百度 key。不再拍板"部分类别靠种子数据垫底",或切换到高德/百度 key(数据全但需注册)。

3. **地图瓦片在国内访问** → OSM 瓦片国内可用性一般,阶段 1 先用自由瓦片,若加载慢再换(高德瓦片或本地缓存)。
4. **React vs 原生**:默认原生+Leaflet 起步;若神朱计划快速产品化,可在 1a 前定夺是否直接上 React。
